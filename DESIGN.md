# DESIGN.md — Архитектура проекта Bulls and Cows

## 1. Структуры данных и алгоритмы

### Управление состоянием (State Management)
Для строгого соблюдения принципов функционального программирования и иммутабельности, всё состояние приложения централизовано в едином объекте `GameState`. История попыток хранится в виде массива объектов типа `Attempt` (`{ guess: string; bulls: number; cows: number; }`). 

Обновление состояния происходит исключительно декларативно: функция `addGameAttempt` не мутирует существующий массив через `.push()`, а генерирует новое состояние с помощью оператора spread:
`history: [...state.history, newAttempt]`
Это полностью предотвращает непреднамеренные побочные эффекты.

### Алгоритм evaluateGuess
Функция выполнена без использования классических императивных циклов со счетчиками (`for`, `while`), как того требует техническое задание. Сверка строки ввода с секретным числом реализована через декларативные методы массивов:
1. **Bulls (Быки):** Вычисляются с помощью метода `.filter()`, который сравнивает символы попытки и секретного числа на строго одинаковых позициях (индексах), после чего берется свойство `.length`.
2. **Cows (Коровы):** Вычисляются через метод `.filter()`, проверяющий, что символ присутствует в секретном числе (`.includes()`), но при этом его текущий индекс не совпадает с индексом в секрете (то есть он не является «быком»).

### Алгоритм countPossibleSecrets
Расчет количества уникальных комбинаций основан на формуле перестановок без повторений: $P(base, length) = \frac{base!}{(base - length)!}$.
Алгоритм реализован рекурсивно на основе математической связи:
`countPossibleSecrets(length, base) = base * countPossibleSecrets(length - 1, base - 1)`
Для оптимизации и исключения избыточных вычислений при частой смене настроек применен паттерн **Мемоизация**: результаты кэшируются в объекте `memo` по уникальному ключу `${length}-${base}`. Если значение уже вычислялось ранее, оно мгновенно возвращается из памяти за $O(1)$.

## 2. Сложность алгоритмов (Big O Notation)

* **`generateSecret(length, base)`**: В худшем случае сложность составляет $O(length \times base)$ из-за итеративного поиска уникальных символов с помощью метода `.includes()`. Учитывая жесткие ограничения в правилах игры ($length \le 6$, $base \le 16$), алгоритм выполняется за константное время $O(1)$.
* **`evaluateGuess(secret, guess)`**: Сложность составляет $O(length^2)$, так как для каждого символа из массива `guess` вызывается метод `.includes()`, сканирующий массив `secret`. При максимальной длине числа в 6 символов алгоритм работает мгновенно.
* **`isValidGuess(guess, length, base)`**: Сложность $O(length \times base)$. Операция фильтрации алфавита занимает $O(base)$, проверка на уникальность символов через `Set` занимает $O(length)$, а финальный предикат `.every()` проверяет каждый символ за $O(length \times base)$.
* **`countPossibleSecrets(length, base)`**: Без кэширования сложность рекурсии составляет $O(length)$. Благодаря внедрению **мемоизации**, вычислительная сложность повторных вызовов снижается до константной $O(1)$.

## 3. Принципы чистого кода (Clean Code)

В ходе разработки были интегрированы следующие фундаментальные концепции:
1. **Single Responsibility Principle (Принцип единственной обязанности):** Ядро игры (`gameLogic.ts`) полностью изолировано от уровня представления (DOM-дерева) и занимается исключительно чистыми математическими расчетами. Это позволило легко покрыть логику изолированными модульными тестами в Vitest.
2. **KISS (Keep It Simple, Stupid) и Декларативность:** Вместо сложной ручной синхронизации данных с элементами интерфейса, архитектура приложения построена на сквозном рендере. При любом изменении состояния вызывается функция `renderApp()`, которая полностью очищает `document.body` и безопасно выстраивает DOM-дерево заново на основе актуального `state`.
3. **Защита от Магических Чисел:** Все конфигурационные параметры (такие как `MAX_RECORDS = 10` для таблицы рекордов) вынесены в именованные константы, повышая читаемость кода.
